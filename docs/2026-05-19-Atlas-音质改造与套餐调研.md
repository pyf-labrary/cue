## 二、技术架构变化

### 1. Tone 动态导入（commit `ec4cb2e`）

**问题**：M7 fix `04ae1f6` 把 `buildFxBus()` 推迟到首次 `play()`，autoplay warning 从 15 降到 2。剩 2 个不是节点构造产生的，而是 **Tone v15 ESM 模块入口本身就 `new AudioContext()`**——只要 `import * as Tone from 'tone'` 被静态求值，warning 就跑。

**方案**：把所有 Tone 静态 import 改成 `import type * as Tone from 'tone'`（仅类型，TS 编译期擦除），运行时通过懒加载句柄访问：

```ts
let _T: typeof import('tone') | null = null;

function T(): typeof import('tone') {
  if (!_T) throw new Error('[synth] Tone accessed before ensureAudioStarted()');
  return _T;
}

export async function ensureAudioStarted(): Promise<void> {
  if (started) return;
  if (!_T) _T = await import('tone');  // 唯一加载点
  await _T.start();
  started = true;
  buildFxBus();
}
```

涉及文件：

- `src/lib/synth.ts` — 主改造点，所有 `new Tone.X` / `Tone.start` / `Tone.now` / `Tone.loaded` / `Tone.context` 走 `T()` 句柄
- `src/lib/compositionPlayer.ts` — 改 type-only import，引入 `toneNow()` 帮助函数替换 4 处 `Tone.now()`
- `src/lib/spectrum.ts` — 删 `void Tone` 防 tree-shake 的 hack，不再需要

**附带 free win**：Vite 看到 `await import('tone')` 自动 code-split：

- 主包 gzip **186 KB → 81 KB**（-56%）
- Tone 独立 chunk 121 KB gzip，首次 play() 时才加载

### 2. Atlas 真演奏 demo 主播放（commit `a2e7706`）

**根因诊断**（5 条）：

1. 中乐 erhu/guzheng/guqin/choir 借 GM SoundFont（fiddle/koto/shamisen/choir_aahs）的皮——FluidR3 GM 是 90 年代 MIDI 塑料味代名词
2. 5-7 个采样点拉满 88 键，远端 pitch-shift 像变速磁带
3. 手写 PHRASES 机械量化，零 humanize / vibrato / legato
4. 全局只有一条 Tone.Reverb，没有乐器级 EQ/tail
5. 乐句是"练习曲"，5-8 个音 demo "我会发声"，没有起承转合

**M7 已经埋好一半路**：M7 给 4 件 GM 借皮乐器各生成了 12s MiniMax 真演奏 demo，藏在第二个 "听一段真乐器" 按钮里。这次把这条路提为主播放。

**改动链**：

1. `scripts/gen-instrument-real-demos.py`：4 个 prompt → 21 个 prompt（覆盖 atlas 全部乐器），模型从 `music-1.5` 升 `music-2.6`，prompt 锁 "solo unaccompanied, no drums, no bass, no other instruments" 防 MiniMax 配伴奏
2. 跑批量：5 件新 demo 落盘后 MiniMax 余额耗尽（HTTP 1008 `insufficient balance`），生成停在 `clarinet`。当前 9/21 件就位：
   - 旧 4 件：erhu, guzheng, guqin, choir
   - 新 5 件：cello, violin, contrabass, pizzicato-strings, flute
   - 待补 12 件：clarinet, oboe, french-horn, trumpet, piano, xylophone, pipe-organ, pipa, timpani, taiko, celesta, synth-pad
3. `src/pages/Atlas.tsx` + `src/pages/Instrument.tsx`：主 `PlayButton` 的 `src` 切到 `${BASE_URL}samples/<id>-real.mp3`。删 `cdn(samples/${inst.phrase})` 路径（原本指向从未存在的 `phrase-01.mp3`，每次都 404 → 回落合成器，这是用户感知"很生硬"的另一个直接原因）
4. `Instrument.tsx` 删二级 "听一段真乐器" 按钮 + `REAL_DEMO_IDS` 集合，不再 A/B 对比
5. **优雅降级**：缺 demo 的 12 件走 `audioEngine.playSampleOrSynth` → `onloaderror` → `playSynth` 兜底，用户感知"按播放就响"，只是声音偏合成器

### 3. humanize（commit `a2e7706` 顺手）

`compositionPlayer.scheduleNotes` + `synth.playSynthPhrase` 都加：

```ts
const timeJitterMs = (Math.random() - 0.5) * 24;  // ±12ms
const velJitter = 0.92 + Math.random() * 0.16;    // ±8%
```

应用范围：

- **Sandbox / Lesson 作曲台**：每次播放时合成器 voice 不再 sequencer-quantized
- **Atlas 缺 demo 兜底播放**：12 件没真 demo 的乐器走合成时也活一些

**没改的**：`scheduleDrone`（drone 是长持续音，jitter 反而破坏）+ 真 demo Howl 路径（mp3 本身就是真演奏不需要 humanize）。

### 4. 顺手清理

- `scripts/gen-scene-music.py` + `scripts/gen-instrument-real-demos.py`：env 路径 `~/.minimax.env` → `~/bin/.minimax.env`，跟 `~/claw/bin` 工具栈对齐（M7 遗留 unstaged 改动）

## 五、关键决策

| 决策 | 原因 |
|---|---|
| Tone 用 `import type` + 懒加载，**不** 全异步化 synth.ts 函数签名 | 调用方都在 `ensureAudioStarted()` 之后，运行时 `T()` 句柄是同步访问；只有一处 `await import('tone')`（ensureAudioStarted 内），改动半径最小 |
| Tone 句柄用 throw 而不是 fallback | `T()` 在 ensureAudioStarted 之前被调是逻辑错误，应该崩出来不是悄悄回退 |
| Atlas 试听换真演奏 demo 而不是改 humanize | 改 humanize 只能让"塑料味"变"加了点情感的塑料"；GM 借皮 + 远端 pitch-shift 是结构性缺陷，软改无解 |
| 真演奏 demo 用 MiniMax music-2.6 而不是找 CC 真录音 | 一键脚本可复现 + ¥1/首 + 12s 是真演奏；CC 录音找+裁+对齐授权要 4-6h；ROI 远低 |
| humanize 不动 drone clip | drone 是长持续音，attack 时间抖动会让"持续音"变成"飘忽" |
| 缺 demo 走静默兜底合成 + humanize | 用户感知 "按播放就响" > "按播放报错"；humanize 让兜底也不那么死 |
| 主播放 src 直接指向 `samples/<id>-real.mp3` 而不是新字段 `inst.realDemo` | 21 件全统一命名，硬编码规则比加 data 字段更清晰；`inst.phrase` 字段保留但已不读 |
| 删第二个 "听一段真乐器" 按钮 | 真 demo 升为主之后 A/B 对比没必要；少一个按钮少一份歧义 |
| 两个 commit 拆分 | Tone 懒加载是纯重构 + perf，Atlas 改造是 feature；语义清晰利于回退 |
