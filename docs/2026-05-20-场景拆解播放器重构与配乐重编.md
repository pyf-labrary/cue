## 二、关键背景：MiniMax music-2.6 能力边界（本次起因）

用户问 MiniMax music-2.6 能否「时间戳精确控制 + 控制生成长度」。结论：

- **不能**。`/v1/music_generation` 无 duration 参数（长度由 lyrics/结构标签间接决定，2–6 分钟），无任何 per-timestamp 控制。
- 各家对比：长度可数值控的有 **ElevenLabs Music**（composition plan + `respect_sections_durations`，每段 `duration_ms`）、**Stable Audio 2.5**（`duration`，上限 3min）；Suno 是生成后 crop/extend/warp。**帧级卡点没有任何 text-to-music 能做**，仍归 DAW 或 Tone.js 程序化。

→ 直接推翻了之前「用 MiniMax 整曲当场景 MX」的做法（见下）。**详见 MEMORY: `feedback_cue_scene_mx_synth`**。

## 三、技术细节

### 1. MX 轨回退合成（`d6fe41e`）

**问题**：5 个场景的 MX 挂的是 MiniMax 生成的 `public/scenes/*/mx.mp3`。mp3 真实时长（55.7/40.7/30.9/73.2/35.3s）跟代码 `durationSec` 全对不上；曲内事件也跟导演笔记 annotation/tick/播放头落点错位。之前为迁就 mp3 把合成时间码 ×1.5~2.8 拉伸，连合成版都走形。

**方案**：删 5 处 `mxAudio`/`mxAudioGain`，MX 走回 `tracks.mx` 的 Tone.js 合成分支；时间码还原到原始栅格（`git checkout db94528 -- scenes.ts` 取的）；删 5 个 mp3（7.3MB，`gen-scene-music.py` 可重生）。`mxAudio`/AudioClip **基础设施保留**（真录音是受支持能力，将来接 ElevenLabs 这类可定长的才用）。

### 2. 进度条卡顿（`5da4c89`）

三个叠加病因：

1. 播放头 `transition: left 0.05s` 被 rAF 每帧重设目标 → 橡皮筋回弹（「忽快忽慢」）。
2. 播放引擎每帧 `notify()` → 整个五轨树（5 轨 × ~50 mark + 频谱）60fps 全量重渲染丢帧（「卡」）。
3. `SpectrumStrip` 每帧 `getBoundingClientRect()` 读 layout，与播放头写 `left` 互相触发**强制同步重排**。

**方案**（核心是把位置从 React 渲染解耦）：

- 新增 `src/lib/usePlayhead.ts`：单条 rAF 把 0..1 进度写进 CSS 变量 `--p`，DOM 用 `transform: scaleX(var(--p))`（ScrubBar 填充）/ `left: calc(var(--p)*100%)`（轨道竖线）定位，**无 transition、不经 React state**。
- `compositionPlayer` 加 `nowSec()`（实时墙钟读取口）；ticker 的 `notify()` 节流到 ~10fps（只喂时间读数/导演笔记）。
- `SpectrumStrip` 尺寸缓存进 ResizeObserver 回调，rAF 内不再 `getBoundingClientRect()`。

实测：播放头速率 p5/p50/p95 ≈ 3.85e-5 frac/ms（理论值正中），0 回退、0 停顿帧、≈60fps。**详见 MEMORY: `feedback_cue_playhead_perf`**。

### 3. 布局对齐 + 频谱（`5da4c89`）

- slider 之前跨满内容宽（49→1231px），五轨 track 只在中列（165→1155px）→ 进度看着对不上。
- 方案：slider 放进与五轨**同一 grid 列**（`[100px_1fr_60px]` + gap-4，首尾空占位），五轨第三列 `auto`→固定 `60px`。实测 slider 与 track 像素级重合（165→1155）。
- 频谱移回 header「回到起点」右侧，去 `max-w-[280px]` 改 `flex-1` 拉伸（280→919px），柱数 `NUM_BARS` 32→64。

### 4. 五场景配乐重编（`c5f7940`）

按用户「两者都做（更忠实母题 + 更丰满）」重写，先做 Jaws 样板确认风格后推平其余 4：

- **Jaws**：E–F 半音 cell 四相位渐快渐强 + 大提琴低音涌动 + 圆号半音浪×3 + 定音鼓心跳渐强连击 + 水下 pad（26→30s）。
- **卧虎藏龙**：D 小调五声音阶 cello/erhu 四度对位 + 古筝竹叶 8n + 长笛抬升（22→28s）。
- **Psycho**：小二度尖叫(E6+F6)叠低音弦下捅 + 9 次渐快连击 + 下行收束（18→22s）。
- **Interstellar**：C pedal 全程不动 + 招牌上行琶音动机 + 移动和声 + 人声合唱（26→36s）。
- **教父**：步伐 + d 小调小号哀歌（evoke 非扒谱）+ 圆号低八度应答（24→30s）。

> ⚠️ **出处/版权**：这些音符是 **Claude 手搓的教学重构、无乐谱出处**。真实只到「招牌手法/事实」层（E–F、高音弦尖刺、管风琴 pedal 等）；具体音高/节奏是为采样器凑的近似。**教父、卧虎藏龙是成段旋律，走「还原乐器音色 + 旋律轮廓」的 evoke 路线，不逐音扒谱**（版权 + 站点本就声明「不是从原片剪的」）。

### 5. 情绪预览：同曲 bug → 单音色（`e5a6645` + `d7c7db4`）

**问题**：`Home.previewEmotion` 播的是「第一件 signature 乐器的通用乐句」（`audioEngine.playSynth(first)`），首乐器相同就完全同曲——joy/playful 都 flute、suspense/romance 都 violin。

**方案**：
- `emotions.ts` 加 `PreviewNote` 类型 + `EMOTION_PREVIEWS`（每情绪一段专属乐句）。
- `composition.ts` 加 `emotionToComposition(id)`（按乐器分组成 NoteClip）。
- `Home.tsx` 预览改走 `compositionPlayer`，离开页面 `stop()`。
- 用户嫌多乐器层叠乱 → 收成**单音色**：每情绪一件乐器，**12 件 lead 互不重复**，靠音区/调式/节奏区分。映射见 `EMOTION_PREVIEWS` 注释（喜悦=长笛 / 嬉戏=木琴 / 浪漫=小提琴 / 悬疑=钢琴单点 …）。

## 四、踩坑 / 环境约束

1. **dev server 后台进程在 agent 沙箱里跨工具调用不存活**：`(npm run dev &)` 起的服务下一次 Bash 调用就没了，且端口状态混乱。可靠做法是**让用户自己 `npm run dev`，agent 只跑 Playwright 探针连 localhost:3333**。
2. **`gh` Actions API 403**：`pyf-labrary` org 禁止生命周期 >366 天的 fine-grained PAT 访问 Actions API。`git push` 用的是另一套凭据、推送正常、部署照跑——只是 `gh run` 查不了状态。验收直接看线上。（已记 MEMORY: `feedback_github_ops`）
3. **MiniMax music 不可定长/对齐**（见第二节），场景 MX 永远走 Tone.js 合成。
