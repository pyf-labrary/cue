## 三、技术架构概览

### 双播放器并存
- **新引擎** `compositionPlayer` — 可编辑 Composition，clip 级 mute/vol，rAF + walltime 同步。用在 Sandbox + Lesson 所有 widget。
- **老引擎** `scenePlayer` — 固定 Scene 输入，单例。用在 SceneDetail。可以下一步迁移到新引擎删除。

### 5 轨约定
DX（对白）/ MX（音乐）/ FX（音效）/ NX（环境）/ VO（旁白）—— 整站统一，每轨独立颜色 + 独立 mute/solo/vol。

### 双采样后端
- 西洋 11 件 + 中乐 5 件用 Tone.Sampler 锚点插值
- 5 件无好采样的（timpani / taiko / celesta / synth-pad / pizzicato）走纯合成 recipe
- 全部经过 Reverb(decay 2.6s, wet 22%) + Limiter(-3dB) 统一 FX bus

### 部署
- `VITE_BASE=/cue/` + HashRouter
- GitHub Actions: checkout → setup-node → npm ci → npm run build → upload-pages-artifact → deploy-pages
- push to main 触发，约 1.5 分钟完成

## 五、关键决策（本次会话新增）

| 决策 | 原因 |
|---|---|
| HashRouter 而非 BrowserRouter | GH Pages SPA-routing 404 问题，HashRouter 零额外配置 |
| 三个 keyboard hook 而非一个 | 避免 Lesson 页面里 transport 和 lane 监听器双触发 |
| `Tone.start()` 推迟到 play() | autoplay policy 下 Tone.start await 永远阻塞，会卡 status=loading 让 play 按钮永久 disable |
| Composition 数据驱动 vs 直接 Scene | 让 Sandbox 和 Lesson widget 共用同一引擎 + 数据结构；Scene → Composition adapter 桥接旧场景 |
| GitHub Actions workflow 部署而非 push to gh-pages | 避免 `dist/` 进 git，部署逻辑明确，PR 可见构建日志 |
| 视觉资产用 Dreamina 5.0 而非自画 SVG/Lottie | 20+5+5+1 = 31 张 cinematic 图像用 SVG 不可能达到同水准，每张 ¥2 在预算内 |
| Atlas 卡片改成肖像 + overlay 而非文字卡 | 视觉密度立刻上一档；图标清晰度优于文字识别 |
| 类别 icon 用 inline SVG 而非 emoji / 字体 | feedback_no_emoji_in_render：Linux Chromium 无色 emoji 会渲染豆腐块 |
